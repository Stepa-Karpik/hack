# Данные и обучение

Все обучающие страницы **сгенерированы**: люди, организации, номера и даты в них вымышлены. Документы организаторов, реальные бенчмарки и реалистичные бланки используются только для оценки и в обучение не попадают. Сами наборы в репозиторий не входят: их можно воспроизвести генераторами из этого раздела.

## Источники

### Генератор v5

На каждой странице варьируются:

- **Шапка и реквизиты:** шапка организации и адрес, строка «дата + номер», заголовок (16 вариантов).
- **Поля:** разные подписи («Ф.И.О.», «Рег. №», «Место прохождения практики» и т. д.), разделители `:`, `—` и пробел, около 12% пустых значений.
- **Текст:** абзацы Википедии, иногда со вставкой «Настоящая справка выдана …».
- **Подписи и печати:** подпись должностного лица, «М.П.».
- **Плотность:** 2–4 абзаца, мелкий кегль, в 30% случаев две колонки.
- **Оформление:** 4 размера страницы, поля, интервал, выравнивание, курсив и полужирный, цвет чернил, тон бумаги.
- **Дефекты скана:** поворот до ±0,7°, размытие, JPEG 45–85.

Цель обучения повторяет то, как модель на самом деле выводит текст: строки одного блока склеиваются в абзац, а блоки разделяются пустой строкой. Это поведение заранее проверено пробным прогоном (`--convention`).

### Генератор marks-v1

Генератор воспроизводит ситуации, в которых ошибалась прежняя голова:

- блок подписи «Должность ____ И.О. Фамилия» с подписью поверх линии над «(подпись)»;
- подписи из вырезок Ultralytics (train-вырезки идут в train и val, val-вырезки — только в test) или процедурные росчерки;
- круглые и прямоугольные печати разного цвета, перекрывающие текст рядом с «М.П.»;
- негативы: пустая строка с «(подпись)», «М.П.» без печати, цветные круглые логотипы в шапке.

Для каждой отметки сохраняется рамка.

## Проверки утечек

Перед обучением автоматически проверяется:

- каждая строка помещается внутри страницы, рамки строк не пересекаются;
- SHA-256 пикселей всех страниц уникальны;
- у train и test нет общих семейств шрифтов, фамилий, статей и seed;
- у v5 и v4b нет общих фамилий.

Контактный лист страниц просмотрен вручную.

Найденная утечка: в Wikidata «Галямов» и «Галямова» — две разные записи, и они попали в разные части. Страница `test-036` исключена из оценки, это отмечено в отчёте (`grade_natural.py --exclude`).

## Обучение LoRA v5

```bash
python -m scripts.unified.prepare_natural_pages --sources work/ocr-v5/sources --output work/ocr-v5/data-v5
python -m scripts.unified.train_natural_v5 \
  --base work/paddle-vl-base-v1 \
  --init-adapter models/unified-experimental-literal-values-fp32-v4 \
  --v5 work/ocr-v5/data-v5 --v4b work/unified-literal-values-v4b \
  --head models/unified-experimental-graphic-head-fp32-v3 \
  --graphic-inputs <24 контрольных изображения> \
  --convention paragraphs --output work/ocr-v5/lora-v5
```

Порядок работы:

1. **До запуска** фиксируются гипотеза, параметры и проверки ([model.md](model.md#адаптер-lora-v5-modelsunified-experimental-natural-v5)).
2. **Контрольные точки** сохраняются на шагах 80, 160 и 240, но оценивается только финальная 240. Выбора точки по результатам нет.
3. **Защита vision.** До и после обучения сравниваются хэши vision-параметров, а также признаки и оценки графической головы на 24 контрольных изображениях.

## Обучение патч-головы

```bash
python -m scripts.unified.prepare_mark_pages --sources work/ocr-v5/sources --signatures data/detection/source --output work/marks-v1/data
python -m scripts.unified.train_mark_patches --output work/marks-v1/head
python -m scripts.unified.select_mark_rules --scores work/marks-v1/head/heldout-scores.json ... --kit <kit> --head models/unified-experimental-mark-patches-v1
```

Признаки патчей извлекаются тем же замороженным энкодером, что и при распознавании. Порог и правило выбираются **только на val**. Test, документы организаторов и реалистичные бланки только оцениваются.
