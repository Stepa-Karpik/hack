# Безопасность и данные

## Обработка данных

- **Локальная обработка.** Распознавание, извлечение полей и ответы ассистента выполняются собственными моделями на сервере или на подключённом агенте. Внешние API OCR и языковых моделей не используются.
- **Кадры камеры** живого режима обрабатываются в памяти и удаляются сразу после ответа.
- **Документы** хранятся в каталоге данных сервера (`documents/<slug>/`) вместе с версиями. Владелец удаляет свой черновик, сотрудник — закрытую заявку.
- **Ссылки** на заявки содержат 21 случайный символ. Знание ссылки не даёт доступа: каждая операция проверяет владельца или роль.

## Роли и права

| Действие | Студент | Сотрудник | Суперадмин |
| --- | --- | --- | --- |
| Загружать, проверять, отправлять свои документы | ✓ | ✓ | ✓ |
| Видеть чужие заявки (кроме черновиков) | — | ✓ | ✓ |
| Одобрять, возвращать, закрывать | — | ✓ | ✓ |
| Ставить свою подпись в редакторе | ✓ | ✓ | ✓ |
| Ставить печать деканата | — | ✓ | ✓ |
| Приглашения, роли, конструктор типов | — | — | ✓ |

- Сотрудник регистрируется только по одноразовой ссылке-приглашению. Ссылка действует 7 дней и может быть отозвана. В базе хранится хэш токена.
- Суперадмин не может снять роль администратора с самого себя.

## Целостность документов

- Редактор ставит только подпись текущего пользователя из его профиля и печать деканата только для сотрудников.
- Каждая правка в редакторе и каждая замена файла создают новую версию. Прежняя версия сохраняется в `history/v<n>/` и доступна деканату.
- В журнале заявки фиксируются автор и время каждого действия, а для правок в редакторе — их содержание («подпись; текст …»).
- Сервис проверяет наличие подписи и печати, но не их подлинность. Решение о принятии документа принимает сотрудник деканата.

## Аутентификация

| Механизм | Устройство |
| --- | --- |
| Пароли | PBKDF2-HMAC-SHA256 с солью |
| Сессии | Cookie `HttpOnly`, `SameSite=Lax`, флаг `Secure` за HTTPS; при смене пароля остальные сессии завершаются |
| API-ключи | `dk_live_…`; ключ показывается один раз, в базе хранится хэш |
| Изменяющие запросы | Проверка заголовка `Origin` для запросов из браузера |
| Агент | Токен в `Authorization: Bearer`, сравнение за постоянное время |
| Лимиты | nginx: запросы к `/api/auth/` и загрузкам ограничены по частоте |

## Ассистент

Ассистент отвечает только по распознанному документу и Положению. Ответ, в котором есть дата, номер или ФИО, отсутствующие в документе, отклоняется проверкой привязки. Если сведений нет, ассистент говорит об этом и направляет в деканат. Попытки заставить ассистента «принять документ» отклоняются: решение принимает сотрудник (п. 1.3 Положения).
